# ADR 005：单知识库管理控制面

> 状态：第一版决策仍有效；单知识库限制已由 ADR 006 替代。

## 背景

项目原先只在应用启动时扫描 `CHATBOT_DOCUMENTS_PATH`，缺少运行期上传、状态持久化、切片
检查和召回诊断。后续还可能演进到多知识库、对象存储、版本回滚和批量评测，但
第一版只允许管理当前一个知识库，且不得重构现有聊天页面。

## 备选方案

1. 每次上传后重新扫描整个目录，不保存管理状态。
2. 把文件和任务状态都写入 Qdrant payload。
3. 增加轻量控制面目录，由现有 AgentScope/Qdrant 链路继续负责索引和检索。

方案一无法可靠表达失败和重启恢复，替换期间也难以保护旧版本。方案二混淆控制面与检索
数据，使任务状态和原文件生命周期依赖向量存储实现。

## 决策

采用方案三：

- SQLite 保存逻辑文档、不可变原始版本和任务状态。
- 本地文件模块保存版本文件和当前活动原文件。
- Qdrant payload 是最终索引切片的真实来源，切片浏览直接读取该 payload。
- 单工作协程顺序执行索引和删除；运行中任务在启动时恢复为排队状态。
- 替换使用新的向量文档标识，成功后删除旧向量；失败时恢复旧活动文件和旧索引。
- 管理 API 与聊天 API 分离，但不提供应用内管理员登录或身份校验。
- Next.js BFF 只负责同源转发、路径校验和错误映射，不维护管理会话。
- 前端只向现有侧栏注入固定“知识库”入口，不改变聊天主体和 assistant-ui Runtime 契约。

## 后续演进约束

- 数据记录保留稳定 `knowledge_base_id`；多知识库创建与隔离见 ADR 006。
- 文件操作集中在服务边界，未来可替换对象存储，不提前实现云适配器。
- 摄取用例基于不可变内容版本和来源元数据，未来网页或定时同步可以复用。
- 召回诊断返回结构化阶段结果，未来离线评测直接调用同一检索流程。
- 聊天附件是独立协议，不得把管理上传接口暴露给普通聊天用户。
- 未来 Agent 追踪必须与公共聊天流分离，且不得记录或展示隐藏思维链。
- 管理面只适用于本地或受信网络；远程部署必须在应用外部增加访问控制。

## 影响

该 ADR 落地时限制为单进程任务执行和单知识库。ADR 006 已解除单知识库限制；多实例部署
前仍必须引入共享任务协调。
