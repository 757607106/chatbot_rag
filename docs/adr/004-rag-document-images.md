# ADR 004：使用文本召回关联文档图片

## 状态

已采纳。

## 背景

知识库同时包含 Markdown 外链图片、Word 内嵌图片和 PDF 页内图片。Web 对话需要在
回答中稳定显示与检索文本相关的图片，但当前索引使用 `text-embedding-v4`，聊天前端
使用 assistant-ui `LocalRuntime` 与项目自有 NDJSON 协议。直接把图片 Base64 放入
向量库或流协议会扩大存储与消息体，也不能解决图片权限和来源地址泄漏。

## 决策

1. 保留文本 embedding。解析器把图片保存或登记到 `MediaAssetStore`，并在相邻文本中
   写入内部媒体标记；图片本身不进入 embedding。
2. Markdown 远程图片仅接受配置允许主机上的 HTTPS 地址，首次读取时由后端校验状态、
   MIME、文件签名和 10 MB 上限后缓存；不允许重定向。
3. Word 使用 AgentScope 2.0.5 `WordParser(include_image=True)` 取得 `DataBlock` 后保存，
   PDF 使用项目 parser 按页提取文本与图片。最终交给
   `ContextPreservingChunker(ApproxTokenChunker)` 的内容仍是 `TextBlock`，避免文本
   模型接收图片数据；Markdown 图片保留在所属标题章节内，不作为独立语义边界。
4. 每个源文档提交图片清单；摄取管线版本参与文档版本 ID。文档删除、图片减少、媒体
   清单丢失或管线升级时同步重建索引并清理无引用资产。
5. `search_knowledge` 的内部工具结果事件提供本轮允许使用的媒体标记。模型采用标记相邻
   的证据时，将原标记放在对应说明之后；HTTP 层读取工具结果但不公开其参数或原文，
   并跨回答文本增量解析标记，在原位置输出版本 2 `image_part`，不再把所有命中图片
   统一追加到回复末尾。
6. HTTP 层只转换属于本轮检索结果、首次出现且位于每次回复前 3 个的标记；事件只包含
   同源媒体 URL 和文件名。每张图片前还必须有自上一张图片后新增的非空正文；编造、
   跨轮复用、连续、重复及超量标记均不进入公共协议。
7. 前端 `ChatModelAdapter` 将事件累积为 assistant-ui 原生 `ImageMessagePart`；Next.js
   BFF 转发媒体内容，组件负责加载、失败、焦点和预览状态。

## 备选方案

- **让模型输出 Markdown 图片**：无需协议转换，但模型可能遗漏、改写或编造 URL，也会
  把外部地址和访问行为直接暴露给浏览器。当前只允许模型复制不含 URL 的受控内部标记，
  并由协议层按本轮检索允许列表校验。
- **图片 Base64 进入 NDJSON**：assistant-ui 可以显示 data URL，但当前事件有 128 KB
  上限，大图片会增加内存、延迟和历史消息体积。
- **全面使用多模态 embedding**：能够按视觉内容检索，但需要更换 embedding 模型、
  重建 Qdrant collection，并验证聊天模型的多模态输入，超出当前“展示相关图片”目标。

## 影响

- 摄取阶段新增媒体目录和管线版本；首次升级会重建已有文档索引。
- 远程图片首次打开需要一次后端下载，后续从本地缓存读取。
- 图片只能随相邻文本被召回，无法回答纯视觉相似度问题；该能力若成为明确需求，需新增
  ADR 评估多模态索引。
- 图片位置由模型依据检索内容中的相邻关系选择；模型未在回答中引用的图片不会显示。
- 当前应用尚无用户身份体系，媒体接口沿用同源部署和不可枚举资产 ID；公网开放前
  必须在 Python 媒体路由和 Next.js BFF 同时加入与文档一致的授权校验。
